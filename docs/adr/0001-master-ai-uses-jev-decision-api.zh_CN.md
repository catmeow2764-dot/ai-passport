# JEV 决策否决;JEV 改作棋评

状态:已否决(原计划)/ 已接受(改用)

原计划是联网"大师 AI"调 TypeSafe JEV 决策 API 从候选走法中选最佳。原型验证否决:JEV 文档明确称其"不是一个计算器","在需要数字精度或额外间接推理的任务中表现吃力"——而象棋战术(吃子/将军/多步前瞻)正需要这些。探针证实:战术残局(红车可吃无保护黑马)三个 state 提案都没选吃子,印证文档缺陷。

替代方案——本地 negamax 深度提升(depth 6→8)+ 开局库——同样否决:depth 8 在 ESP32-C3 上栈/时间成本增,开局库需数据整理,而现有 depth-6"高级"已够强。

JEV 改作"棋评":每回合一次局面语义评估(谁占优/攻势/阶段)显示给玩家,不参与走法决策。这发挥 JEV 的强项(语义判断),不越界进入它做不了的计算。
